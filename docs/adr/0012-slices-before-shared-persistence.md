# Slices come before shared persistence

**Context.** ADR 0009 and ADR 0011 make the handler the owner of data access and of the commit. They say what a shared read filter or query service may look like, not when it may be written. A module planned in layers (domain, then persistence, then handlers) has to decide how each aggregate is loaded and saved before a single use case exists to say what loading and saving that aggregate requires. Registry, Operations and BackOffice are still empty, so the order in which they are built is still open.

**Decision.** A module is built **outside-in**: the domain the use cases need, then **whole slices** — handler plus the persistence that slice requires, written together — and only then, if two slices demonstrably need the same thing, something shared. Shared persistence is extracted from working slices; it is never written ahead of them. A plan that orders its phases domain → persistence → handlers is ordered wrongly: `plan-and-split` orders them by slice.

**Why.** The use case determines which data must be loaded, in what shape, and what "saved correctly" means. Written first, persistence answers those questions by guessing, and a guess that must cover every future caller generalises: it becomes a service that loads, saves and decides, and then needs a guard so that callers who do not exist yet cannot use it wrongly. That is how a violation of ADR 0011 arrives without anyone choosing it. Written after, the same code is a few lines inside the one handler that needs them, and the question of a shared abstraction is answered by evidence rather than by anticipation. The domain does not suffer from being written first: entities, value objects and invariants do not depend on the shape of a use case.

**Consequences.** Duplication between slices is expected and accepted; ADR 0009 already pays that price deliberately. Duplicating a *rule* is not the same thing: when slices would each restate a decision, the rule moves into the domain as a pure function and the slices call it, leaving only the query and the write in the slice. The decision to share is taken at the moment the second slice needs it, not before the first.
